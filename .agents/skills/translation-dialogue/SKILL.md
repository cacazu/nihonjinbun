# 翻訳・辞書・読書HTMLの作業手順

このリポジトリの翻訳・辞書・読書サイトを整備する際に使用する。本文の保存形式はルートの `TRANSLATION_YAML_SPECIFICATION.md` に従う。辞書やHTMLだけの依頼で、未依頼の翻訳・口調改訂・公開範囲の拡大を行わない。

## 必須の作業順序

**ルート README.md → この SKILL.md → 各作品フォルダの README.md → 翻訳作業** の順を守る。

1. ルート README で対象作品・対象範囲を確認する。このスキルを読んでから、対象YAMLを置く作品フォルダの README を開く。
2. 作品 README がない場合、翻訳より先に原文を通読し、実際に登場する人物・発話集団を洗い出して作成する。既存の場合も、対象回の人物・場面を網羅しているか確認する。
3. 人物・発話集団ごとに、原文に根拠のある性格、口調、一人称、呼びかけ、語尾、相手や感情による変化を考える。根拠の回・対訳IDを添え、口調の例を**3個**書く。例は創作の口調見本だと明示し、原典の引用や本文追加として扱わない。発言のない人物に口癖を創作しない。
4. 作品 README の口調ガイドを参考に翻訳・改訂する。未登場人物や後の回の性格を先回りして適用せず、対象回の原文と人物関係を優先する。同じ人物でも、師への敬語・仲間への親しみ・敵への挑発を使い分ける。
5. 会話の全発言を原文と照合する。各セリフの前に発言者を付け、口調の一貫性と意味・敬意・感情の保持を確認する。既存訳が適切なら、修正件数のためだけに書き換えない。
6. 問題・修正点を記録し、作品固有の人物判断は作品 README、他作品にも起こる手順上の問題はこのスキルへ反映する。変更した手順でもう一度対象訳を確認する。
7. YAML仕様に従い内容ハッシュ・目録・参照・レビュー状態を整合させ、差分とテストを確認し、依頼対象の変更だけをコミット・プッシュする。変更対象、保持した原文・ID、検証結果、未確認範囲を報告する。

辞書・HTMLのみの作業でも読み順は同じ。人物ガイドの新規作成・口調改訂は対象に必要な場合だけ行い、以下の該当手順へ進む。

## NDL の全文テキストから翻訳する場合

1. 指定された資料ページで書名・著者・版・総コマ数を確認し、**「この資料の全文テキストデータ」から先に取得する**。検索結果の断片、別資料の翻刻、画面に見えている一頁だけを全文の代用にしない。リンク先と取得日時・ハッシュを記録する。
2. 配布物が ZIP なら元 ZIP を未改変で保存し、全体 TXT・コマ別 TXT・座標付き JSON 等の内容を調べる。結合 TXT とコマ別 TXT を二重に本文へ取り込まない。総コマ数との一致、空白頁、表紙、奥付、巻末広告等も確認し、収録範囲と対象外を明示する。
3. OCR を下書きの原文として使い、**元のページ画像で誤字・欠字・段組・縦書きの順序を確認する**。読みやすい文になるという理由だけで文字を補わない。「〓」等の欠字、固有名詞、数字、否定語、引用、読順の崩れは特に照合する。画像を見ていない箇所を照合済みとしない。
4. 原 OCR は保持し、画像で確認した原文を YAML の `source_text` に、対応する OCR 原形を `source_variants` の `kind: ocr` に残す。`source_locations` にコマ・原刊頁・実際の画像／資料 URL を記録し、必要に応じて `source_alignment` に配布 JSON の単位 ID を保持する。補訂の内容・根拠と画像確認範囲を記録し、判読不能は Issue と既知の留保へ残す。原典自体の誤記と OCR 誤りを混同しない。
5. 校訂した原文の意味・引用関係・順序を保って現代日本語へ訳し、既存の翻訳 YAML 仕様で保存する。画像にあるが OCR にない本文・見出し・注・図中文字を落とさず、柱・頁番号・蔵書印は本文と区別する。改頁をまたぐ文の接続も確認する。全文取得、画像照合、翻訳、独立レビュー、YAML 検証はそれぞれ実施範囲を区別して報告する。

### 長期作業の進捗と部分保全

- 進捗は「確認済み X コマ／資料全 Y コマ」と、本文・細字・独立校閲の段階を分ける。割当範囲が終了しても全冊完成と呼ばない。前の記録の確認範囲を新しい成果物へ無条件で引き継がない。
- 未完成原稿を保全する場合、原資料ID・対象範囲・未検証事項・実際の確認方法を明記し、状態と構造を見直した部分チェックポイントとして保存する。正本・目録・読書HTMLの完成版とは分離し、未完の意味校閲を済んだことにしない。
- 公開リポジトリへ置くのは依頼された資料・原稿・校訂根拠・成果物状態だけとする。非公開の連絡文、内部調整メモ、実行セッション情報、会話識別子等は含めない。
- 作業ファイルが失われた場合、残存記録からの部分再構築と元ファイルの復元を区別する。復旧原稿は新たな画像照合と内容校閲を行い、以前の確認記録だけで完了へ戻さない。

この手順は原典取得と翻訳の方法であり、HTML 生成・サイト公開や別作品の追加を自動で許可するものではない。

### 検索結果から複数作品を依頼された場合

- 指定された検索結果の全ページを実際に読み、書名・著者役割・資料ID・刊年・版を一覧化する。既訳判定はファイルの存在だけでなく、収録範囲と未訳単位の有無を確認する。APIの失敗だけで表示中の検索結果も取得不能と判断しない。
- 別版を除くよう指定された場合は、一作品につき完整で判読可能な一版だけを選び、採用IDと除外IDを記録する。既訳作品の別版比較や重複翻訳へ広げない。
- 「リストアップ→翻訳→YAML→見直し→プッシュ→HTML→見直し→プッシュ」と指定された作業では、一覧を先に報告し、作品ごとに原稿の見直し・検証・プッシュを終えてから読書HTMLを生成する。原稿反映とHTML公開を別のコミット・プッシュとして記録し、最後に実際の公開URLを確認する。未完了の他作品を完了扱いにしない。

## 共通辞書と各話の初出

西遊記では、作品 README の「各話初出の読み・難語説明と西遊記辞書」を読んだうえで、[辞書の項目・根拠の仕様](../../../lexicons/README.md)と[翻訳YAML仕様8.1](../../../TRANSLATION_YAML_SPECIFICATION.md#81-共通辞書と原稿ごとの初出)に従う。

- **共通辞書** `lexicons/xiyouji.yaml` は西遊記全体で一つ。語の意味 `definition_ja`、意味の根拠 `definition_evidence`、別名・称号・異表記の `forms`、各formの `reading`、出典を保存する。同じ人物の別名は同じentryのformsにまとめる。回ID・段落ID・初出位置・本文表示を辞書へ入れず、辞書を翻訳原稿として `catalog.yaml` へ登録しない。
- 同表記・同姓というだけで既存entryへ結び付けない。人物・役割・地名・一般語の語義と、原文での同一性の根拠を照合する。同一性が未確定なら既存の定義を広げて同一人物にせず、役割を限定した別項目と留保を用いる。別項目は別人であるとの断定ではない。
- 旧字・新字・異体字などの表記差も、既存の見出し・別名・定義・根拠と照合する。人物だけでなく、同じ概念・制度・道具の同一語義と確認できる表記は、同じentryのformsへ追加する。文字列の不一致だけで重複entryを作らず、異なる語義や未確定の同一性は前項の留保を守る。
- **各話の初出** はその回の正本YAMLの `lexicon` に `dictionary_id: xiyouji`、`file: lexicons/xiyouji.yaml`、`first_occurrences` として保存する。各要素は `entry_id`、`form_id`、`segment_id`、`translation_span`、`rendered_text` を持つ。語の登録と、その語を本文で注釈する判断は別にする。
- 各話ごと・各表記（form）ごとに本文の初出を確認し、一件ずつ本文順に記録する。地の文・台詞・発言者名・詩を対象にし、回題・見出し・注本文・説明括弧内だけの出現・長い別名の部分一致は除く。前の回で既出でも、その回の初出には読みを付ける。検索の最初の一致を無条件に採用しない。
- `translation_span` は読みを除く**語そのもの**の範囲。Unicodeコードポイントで0始まりの `[start, end)` とし、`translation_ja[start:end] == exact == form.text` を保つ。`rendered_text` は同じstartからの実文字列 `語（よみ）` と一致させる。仮名だけの表記は読みを重ねず、語だけでよい。同一段落内の初出はstart順に並べる。
- 読みは語の直後の括弧に残す。意味説明を採用する場合は初出要素の `gloss_ja` に分離し、HTMLでは**その本文段落（Segment）の末尾**に `語：意味` として初出順に表示する。意味を読みの括弧へ戻したり、章末へ集約したりしない。詩の改行、発言者ラベル、原訳にある自然な説明文は保持する。読みだけの初出へ、表示変更を理由に意味を新規追加しない。共通語義の改訂だけで既存の `gloss_ja` を自動的に置き換えない。
- 読みを調べても確定できなければ省略せず、根拠を伴う推定を採用する。辞書の `reading.status`・`definition_evidence.status` と `source_ids`・`reason_ja` に確度を残し、資料で確認したものだけを `verified` とする。本文・HTMLの読みに「推定」などの確度ラベルを出さないが、表示を消すために辞書の `estimated` を `verified` へ変えない。本文に関する解釈の留保や必要な訳注は別途保持する。
- 姑・舅など現代の一般的な語に、読みや意味を機械的に付けない。人物名・地名・固有名詞の読みと、古典特有の難解な語義・制度・宗教用語の説明に絞る。本文から注釈を外したら各話の初出記録も合わせるが、共通辞書の語は残してよい。

## 読書HTMLとGitHub Pages

- 正本は各話の翻訳YAML。生成器は `scripts/build_reading_site.py`、CSSの正本は `scripts/reading_site.css`。`docs/` のHTMLやCSSを直接直さず、対象の正本を修正して再生成する。HTML化のために原文・固定ID・順序を書き換えない。
- 公開対象は生成器の `PUBLISHED_CHAPTER_COUNT` と `CHAPTERS` に明示した回だけ。新しい回を依頼に沿って追加するときは、その回の本文・辞書・初出・レビューを整えてから公開範囲を一回ずつ延ばす。`docs/index.html` は索引、`docs/xiyouji/` は西遊記の目次・指定回の `chapter-NNN.html`、`docs/tanaka/` は田中義能の作品一覧・依頼済みの `shinto-taii.html`。共通 `assets/reading.css` と `.nojekyll` を生成し、旧各話URLには移転案内を残す。未依頼の回、辞書、原稿、作業スキルを公開物へコピーしない。
- トップ索引は西遊記・田中義能へのリンクとリポジトリリンクのみ。西遊記目次は既存の題名・翻訳者表記・Xリンク・全回題名と索引への戻りを保持する。各話はタイトル・日本語本文（段落末の意味説明を含む）・注釈と、上下両方の「前の話・次の話・目次に戻る」のみ。第一回には前の話、最終公開回には次の話を付けない。訳注・解釈の留保・出典・帰属・利用条件は注釈欄へまとめる。
- 『神道大意』は正本YAMLの全単位・注釈・順序を保持し、改頁継続の `groups` を連結表示する。OCR補訂履歴は本文へ重複表示せず、原典注記と解釈の留保を保持する。別作品の公開を自動で広げない。
- サイト内リンクは相対パスを維持し、GitHub Pagesのサブパスでも参照できるようにする。現行サイトはJavaScript・表示切替・設定保存・外部フォント・アクセス解析を使わない。旧 `scripts/reading_site.js` とそのテストを、公開サイトに必要なものとして戻さない。
- ローカル表示は `python -m http.server 8000 --directory docs` で配信し、`http://localhost:8000/` を開く。PC幅・スマートフォン幅で改行、読み、段落末の意味、訳注との往復、上下の移動リンクを確認する。単体テストの合格を実ブラウザ確認と呼ばない。

## 対象別の検証とコミット・プッシュ

以下はリポジトリルートで実行する。依存が未導入なら `python -m pip install -r requirements.txt`。対象回のパスは依頼範囲に置き換え、該当する検証を選ぶ。

```sh
# 辞書の語彙・根拠と、対象回の初出・注参照を別々に検証
python scripts/validate_xiyouji_lexicon.py
python scripts/translation_yaml.py translations/wu-chengen/xiyouji-chapter-001-zh-ja.yaml
python -m unittest discover -s tests -p test_xiyouji_lexicon.py
python -m unittest discover -s tests -p test_lexicon_occurrences.py

# 本文・初出・gloss_jaまたは生成器・CSSを変更した場合
python scripts/build_reading_site.py
python -m unittest discover -s tests -p test_paragraph_glosses.py
python -m unittest discover -s tests -p test_reading_site.py
```

- 原稿YAMLを変更した場合は `python scripts/sync_catalog.py` で目録を同期し、対象外の差分がないことを確認する。目録の実バイトハッシュと全文見直し用の内容ハッシュは別物。内容ハッシュの取得は `python scripts/translation_yaml.py 対象回.yaml --hash` だが、実際に全文見直しを完了していなければ `workflow.full_review` を完了へ変更しない。古い確認ハッシュの使い回しや、検証を通すためだけの更新をしない。
- 辞書だけの変更では目録・HTMLの再生成は不要。ただしformの表記・読み・IDを変更したら、利用する各話の初出記録との整合を検証する。文書だけの変更も原稿や生成物へ不要な差分を作らない。
- 共有schema・検証器・目録処理などの変更では、影響範囲に応じて `python scripts/translation_yaml.py`（全原稿と目録）、`python -m unittest discover -s tests`（全Pythonテスト）を追加する。通常の語彙追加では対象別検証を基本にし、機械検証だけで読み・語義・初出判断・網羅性を確認済みにしない。
- `git status --short`、`git diff --check`、差分を確認する。依頼に関係する辞書・対象回YAML・目録・仕様／ガイド・生成 `docs/` を、実際に変更したものだけ明示してstageする。無関係な既存変更を巻き込まず、変更と検証がまとまった区切りでコミットし、設定済みのGitHubリモートの対象ブランチへプッシュする。
- プッシュ前に現在のブランチ・上流・リモートを確認する。リモートが進んでいれば差分を確認して整合させ、強制プッシュや無関係な変更の破棄をしない。CLI認証が使えない場合、利用可能な認証済みGitHub連携で同じ差分を反映し、競合検知付きの通常更新を使う。新しい認証設定を勝手に始めない。失敗・結果不明時はリモートの状態を確認してから対応する。
- リモートのコミットと変更内容を確認してから「プッシュ済み」と報告する。HTMLを更新した場合は、設定済みのPagesのデプロイ結果と確認できた公開URLも確かめる。プッシュ成功・Pagesデプロイ成功・実際の公開表示を区別し、未確認や失敗を明記する。Pagesの公開設定を新設・変更することは、この手順だけでは許可されない。文書だけの変更をサイト表示の更新として報告しない。

## 必須ルール

- 会話のラリー（複数の発言が続くやり取り）では、**各セリフの前に発言者名を付ける**。最初の発言だけでなく、返答・問い返し・短い相づちにも毎回付ける。同じ人物の発言が続いても省略しない。
- 基本形は `悟空「……」`、`祖師「……」` のように、発言者を鉤括弧の直前に置く。既に `悟空は答えた。「……」` のように直前で明記されている場合は、その形を維持し、名前を二重に付けない。セリフの後ろだけの発言者表記では、この要件を満たさない。
- 原文の発話動詞、代名詞、前後の文脈に照らして話者を確認する。登場人物の名称・呼称は作品内で統一する。原文が集団の発言なら `猿たち「……」` のように集団を示す。
- 話者を確定できない場合、人物名を推測して補わない。`話者不明「……」` と明示し、既存の訳注・確認事項の仕組みに不確実性と確認対象を記録する。
- 発言者名は日本語訳に付ける。原文 `source_text` を書き換えない。地の文、詩、引用中の語句を、鉤括弧があるというだけで登場人物の発言に変えない。入れ子の引用は実際の発話と区別する。
- セリフの内容・順序・意味、地の文、対訳単位の固定IDを保つ。発言者表記のために内容を省略・要約したり、未依頼の章を翻訳したりしない。

## 場面ごとの人物名・固有名詞

- 翻訳前に作品 README に呼称表を作る。同一人物の本名・別名・称号・官職、場所・武器の正式名と略称を対応づけ、どの場面からどの呼称が判明し、通常の地の文・ラベルにどの名前を使うかを対訳 ID と文中の転換点で指定する。
- **同じ場面の地の文と発言者ラベルは同じ呼称にそろえる。** 「猴王は尋ねた。孫悟空『…』」のような揺れを残さない。ただし原文の別名・敬称が変わるたびに通常名を切り替えない。物語を追える、既に判明した分かりやすい名前を軸にする。通常名の統一は全人物・全回を通じて保ち、回や場面が変わっただけで既知の名前を「妖怪」「男」等へ戻さない。変装・正体の開示・有意味な呼びかけや詩的表現は個別に判断し、一般名詞を機械的に固有名へ置換しない。名づけ・任官・辞任・自称が一つの対訳単位内にある場合は、その出来事の前後を区別し、自称と正式な授与を混同しない。
- **全人物で、命名・名乗り・正体の判明より前に、後で得る名前や肩書を付けない。** 同じ段落の途中で名が判明する場合も、発言前のラベルから先取りしない。分からない間は、その時点で根拠のある描写名や「男」「声の主」を使う。変身・転生は見た目と話す主体を区別し、判明後は同一人物だと分かるよう接続する。
- **本文だけでなく初出の意味説明も、その場面までの情報で書く。** 共通辞書にある後の法名・正体・結末を、そのまま先の段落の gloss_ja に移さない。原文が明示する予告と、翻訳者が追加する先取りを分ける。
- **訳注は内容だけでなく、リンクの参照起点も開示順に従う。** 同じ段落・詩の末尾で正体・名前・持ち主が明かされる場合、その説明注を冒頭の暗示や未確定の呼称へ付けない。実際に明かす語、またはそれ以後を起点にし、読み進める前のクリックで先取りが起きないことを確認する。段落末の語釈と、途中から開ける訳注は別々に点検する。
- **訳注の追記・改訂後は、元のリンク起点を無条件に継承しない。** 全注の説明全文について、名前・役割・来歴だけでなく、後の行動・内心・発言・落ちまで、そのリンク開始位置で既知か確認する。「直後」「次段落」等の編集上の先取りは、起点を開示後へ移すか、原文本文ではなく当該注の先取り説明だけを狭く改める。同一段落の後半の情報を加えた場合も、その説明が読み終わった位置以後へ起点を移し、本文不変でも参照範囲と内容ハッシュ・HTMLを再検証する。
- セリフ内の呼びかけ・敬称・侮称、名乗り、奏状、引用は話者の認識を優先する。地の文を変えたからといって、敵の旧官職による罵倒や、命名前の人物への後世の名前を一律に置き換えない。

- 底本の異名の重複、古語の字面、対句をそのまま移すと別人・新しい人名・不自然な人称に見える場合は、原文欄を保ち、訳文では同じ人物と意味が追える形にする。編集上の整理と底本の事情は注記し、原文にない人物・結果は作らない。

## レビューと検証

1. 会話をやり取りの開始から終了まで読み、各発言の直前に正しい発言者があるか原文と照合する。話者交代だけでなく、短い返答・同一話者の連続発言・集団発言も確認する。
2. 表記漏れ、誤帰属、呼称の揺れ、名前の二重付与、原文の変更がないことを差分で確認する。文字列検索だけで話者の正しさを保証したことにしない。
3. 訳文を変更した場合は、既存仕様に従って参照文字範囲・レビュー状態・内容ハッシュ・目録を更新し、既存のYAML検証とテストを実行する。実施していない独立校訂を完了扱いにしない。
4. レビュー所見も、引用した実spanの人物・話者・数量・時点・行為の完了／企図と照合する。近接場面の情報を取り違えた所見へ正しい本文を合わせない。所見だけの誤りは記録と重複する報告を狭く訂正し、旧報告と履歴、本文・辞書・HTML等の不変hashを保存する。

## 口調改訂で繰り返さないための注意

- 人物を「傲慢」「無礼」等の一語に固定しない。相手への礼、場面の恐れや感謝まで乱暴な語尾へ変えない。
- 別名・命名前後の名前を同一人物として管理する。名づけ以前の発言者名を、後で得る名前に一律変更しない。
- 一人称・呼称はセリフの話者と相手を確定してから修正する。ファイル全体への機械的な置換は、他人の一人称や引用中の声を壊すため避ける。
- 集団の返答や伝聞・入れ子の引用を一人の発言へ変えない。逆に「私たち／我等」と言っていても、発話動詞の主語が一人なら集団ラベルにしない。「皆に混じって答えた」人物の主語と「皆が答えた」を区別し、前後の文法を確認する。
- 「悟空は答えた。孫悟空『……』」のような導入とラベルの重複は整理するが、笑う・怒る・拝む等の動作や感情は落とさない。鉤括弧の前が人物名ならよいという機械判定だけで済ませない。
- 方言・奇抜な口癖・罵倒を人物らしさのためだけに追加しない。詩、碑文、経典引用、語句の括弧を通常の会話と混同しない。
- 本文の語調だけの改訂でも、既存の注・文字範囲・レビュー用ハッシュが古くなり得る。原文・固定ID・順序の不変を別に確認し、レビュー状態を実際以上に引き上げない。

- 話者ラベルの整形では「兄弟子たち／弟子たち」「さらわれた猿たち／猿たち」のような包含関係に注意する。短い名前への部分一致でラベルを分断しない。整形後の実際の改行と全話者名を見直す。

- 口調を整えるときも、誓い・義務・可能性の強さを変えない。「恩を忘れない」を「必ず恩返しする」に、「必ず」を「かもしれない」に置き換えない。原文にない動機や結果を台詞へ補わない。

## 古典の語義・資料照合

- 慣用句・挨拶・諺は、現代の字面だけで訳さず、その場面の話者・相手・行為と辞書の語義を照合する。同じ挨拶が奏状等に再引用される場合は、引用先でも意味をそろえる。
- 底本の難字・異体字・人物名を、一般に知られる表記や別版の名前へ無断で置き換えない。字義が確定できなければ原字を保持し、訳注や既知の留保として明示する。未確認箇所を省略して全文訳と呼ばない。
- 回題の誇張、人物の主張、語り手の事実説明を区別する。「多くの者」を「全員」に、夢の場面を「実効がなかった」に変えるなど、範囲・因果を補わない。単位の斤・丈等も時代差を無視して確定的な現代単位へ換算しない。
- 新規の回を訳すときは固定版の出典と本文スナップショットを確保し、回題・全散文・挿入詩・書簡や奏状・結語を対訳単位と照合する。本文の区切りや空白の正規化を行った場合は記録し、欠落を機械的にも確認する。

- 移動・侵入・攻撃の動詞を訳すときは、原文が述べる動作と、その結果として起きた破壊を区別する。「押し入る」を、記述のない「門を突き破る」にしない。反語を含む諺は、日本語でも反語だと伝わる形にする。

- 官職・儀礼・武器・固有名の列挙は、その回の本文と語義を優先する。任官を免官、作揖を平伏に変えたり、後世に有名な武器名・姿へ置き換えたりしない。前の回と異なる表記は、無断統一せず相違を記録する。
- 底本の引用符が欠けているときは原文欄を補訂しない。訳文では発話の主語・文脈に基づき引用の範囲を示し、その判断と留保を記録する。人物が伝える発言を、そのまま語り手が確認した事実へ変えない。
